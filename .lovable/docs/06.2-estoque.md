# Documento 06.2 — Regras de Negócio: Estoque & Almoxarifado

> Controle de saldos físicos e reservas de matéria-prima, aviamentos, embalagens e produto acabado.
> Segue o contrato canônico do `06-regras-de-negocio.md`.

---

## 1. Escopo

- Cadastro de **itens de estoque** (SKU interno).
- Múltiplos **depósitos** (almoxarifado central, células, expedição).
- **Movimentações**: entrada, saída, transferência, ajuste, inventário.
- **Reservas** vinculadas a Ficha Técnica, Piloto e OP (PCP).
- **Inventário rotativo** e **inventário geral**.

Fora de escopo: WMS (endereçamento por posição), rastreabilidade por RFID (Fase 3).

---

## 2. Entidades

| Entidade | Campos-chave | Observações |
|---|---|---|
| `stock_item` | code, name, category, unit, min_qty, max_qty | categoria ∈ {tecido, aviamento, embalagem, acabado, insumo} |
| `warehouse` | code, name, type, is_active | type ∈ {central, celula, expedicao, quarentena} |
| `stock_balance` | item_id, warehouse_id, qty_on_hand, qty_reserved | view materializada |

| `inventory_count` | id, warehouse_id, kind, status, started_at, closed_at | kind ∈ {rotativo, geral} |
| `inventory_count_line` | count_id, item_id, expected_qty, counted_qty, variance | |

---

## 3. Fluxos

### 3.1 Movimentação
- Toda entrada exige `ref_type` (recebimento, produção, ajuste) e `ref_id`.
- Saída consome primeiro reservas ativas do mesmo `ref_id`.
- Transferência gera par (`transfer_out` origem, `transfer_in` destino) atômico.
- Ajuste exige justificativa e aprovação de Gestor.

### 3.2 Reserva
`ativa → consumida | cancelada`
- Criada automaticamente ao aprovar OP (PCP) ou piloto.
- Consumida ao lançar saída vinculada.
- Cancelada ao cancelar origem.

### 3.3 Inventário
`aberto → em_contagem → conciliado → fechado`
- Contagem cega (não mostra saldo esperado ao contador).
- Divergências > 2% exigem recontagem.
- Fechamento gera movimentos `adjust` automáticos.

---

## 4. Validações

- `qty_on_hand ≥ 0` (nunca negativo — bloqueia saída).
- `qty_reserved ≤ qty_on_hand`.
- Item bloqueado (`is_active = false`) não aceita novas movimentações.
- Depósito `quarentena` só aceita entrada via QC (Doc 06.4).
- Alerta quando `qty_on_hand < min_qty` (dispara RC — Doc 06.1).

## 7. SLAs

- Recebimento → disponível em estoque: **4h úteis**.
- Reserva de OP: instantânea (síncrona no aprovar).
- Inventário rotativo: ciclo completo em **90 dias** (curva ABC).

---

## 8. Erros

| Código | HTTP | Mensagem UX |
|---|---|---|
| `E_STK_NEGATIVE_BALANCE` | 422 | "Saldo insuficiente para a saída." |
| `E_STK_ITEM_INACTIVE` | 409 | "Item inativo. Reative para movimentar." |
| `E_STK_ADJUST_UNAUTHORIZED` | 403 | "Ajuste requer aprovação do gestor." |
| `E_STK_INVENTORY_OPEN` | 409 | "Depósito com inventário aberto. Movimentação bloqueada." |

---

## 9. Integrações

- **Compras** (06.1): recebimento → entrada.
- **Ficha Técnica** (06): BOM define consumo teórico.
- **PCP** (06): OP consome reservas.
- **Qualidade** (06.4): reprovação move para `quarentena`.
- **ERP** (06.9): saldos espelhados diariamente.

---

## 10. Configurabilidade

- `min_qty` / `max_qty` por item e depósito.
- Tolerância de divergência de inventário.
- Regra FEFO/FIFO por categoria.
- Depósito default por origem de movimento.
