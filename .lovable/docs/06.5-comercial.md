# Documento 06.5 — Regras de Negócio: Comercial (visão PLM)

> **Escopo PLM, não ERP.** O Use Moda **não vende, não fatura, não gerencia pedidos**. Apenas **consome do ERP do cliente** os dados comerciais necessários para orientar o desenvolvimento e a priorização de coleções.

---

## 1. Escopo

O que o PLM **faz**:

- Recebe do ERP: previsão de venda por referência, pedidos em carteira, sell-out por canal, curva ABC.
- Usa esses dados para **priorizar** referências, coleções e sequenciamento no PCP.
- Exibe indicadores comerciais **read-only** ao lado de cada referência/coleção.
- Registra **briefings comerciais** (input do time comercial ao Product Office).

O que o PLM **NÃO faz** (fica no ERP):

- Cadastro de clientes, tabela de preços, política comercial.
- Pedido de venda, faturamento, nota fiscal.
- Comissão, meta de vendedor, CRM.
- Contas a receber, crédito, cobrança.

---

## 2. Entidades (todas locais ao PLM)

| Entidade                  | Campos-chave                                                                            | Origem                     |
| ------------------------- | --------------------------------------------------------------------------------------- | -------------------------- |
| `commercial_briefing`     | id, ref_id \| collection_id, author, target_channel, target_price, target_volume, notes | criado no PLM              |
| `sales_forecast_snapshot` | ref_id, period, qty_forecast, qty_ordered, qty_billed, source, synced_at                | espelho do ERP             |
| `channel`                 | code, name                                                                              | espelho do ERP (read-only) |
| `abc_curve_snapshot`      | ref_id, class, revenue_share, period, synced_at                                         | espelho do ERP             |

Nenhuma tabela de cliente, pedido, NF ou preço vive aqui.

---

## 3. Fluxos

### 3.1 Briefing Comercial

`rascunho → publicado → considerado → arquivado`

- Publicado dispara notificação ao Product Owner.
- "Considerado" é marcado quando vincula a uma referência criada.

### 3.2 Sincronização ERP → PLM

- Job diário (03:00) puxa previsão, carteira, sell-out, ABC.
- Apenas **INSERT** em tabelas `*_snapshot` (histórico imutável).
- Falha de sync gera alerta ao DevOps + banner no dashboard comercial.

---

## 4. Validações

- Briefing exige `target_channel` e ao menos um entre `target_price` / `target_volume`.
- Snapshots ERP: chave `(ref_id, period, source)` única para evitar duplicidade.
- Referências sem match no ERP ficam com badge "sem histórico".

## 6. Permissões

| Papel             | Criar briefing | Ver dados ERP | Vincular briefing a ref |
| ----------------- | -------------- | ------------- | ----------------------- |
| Comercial         | ✅             | ✅            | ❌                      |
| Product Owner     | ✅             | ✅            | ✅                      |
| Especialista Moda | ✅             | ✅            | ✅                      |
| Gestor PCP        | 👁️             | ✅            | ❌                      |
| CEO               | ✅             | ✅            | ✅                      |

Dados ERP **nunca** editáveis pelo PLM — somente leitura.

---

## 7. SLAs

- Sync ERP diária até 04:00. Latência aceitável: 24h.
- Briefing publicado → resposta do Product Office: **5 dias úteis**.

---

## 8. Erros

| Código                      | HTTP | Mensagem UX                                             |
| --------------------------- | ---- | ------------------------------------------------------- |
| `E_COM_ERP_SYNC_FAILED`     | 502  | "Dados comerciais desatualizados. Última sync: {data}." |
| `E_COM_BRIEFING_INCOMPLETE` | 422  | "Informe canal e meta (preço ou volume)."               |
| `E_COM_ERP_READONLY`        | 403  | "Dados originados do ERP. Edite no sistema origem."     |

---

## 9. Integração ERP (Doc 06.9 detalha)

- Contrato: API REST ou arquivo CSV/Parquet diário.
- Adaptadores plugáveis (Protheus, SAP, Sankhya, Bling, etc.).
- Mapeamento de campos via `erp_field_map` (config por cliente).
- Nenhum write-back do PLM para o ERP nesta fase.

---

## 10. Configurabilidade

- Janela de sync (cron).
- Campos ERP mapeados por cliente.
- Canais e classes ABC exibidos.
- SLA de resposta a briefing.
